# Review log — 2026-11-12

Scope: one gate entry point with separately runnable arms, a flat documentation
index, and the documentation facts this repository now carries (GNN pin,
conformance job, action pins).

Evidence is from local runs on the host named in
[`docs/_generated/GATES.md`](docs/_generated/GATES.md). GitHub Actions is
billing-locked for the organisation, so these local runs are the only gate; no
hosted run was observed.

## What changed

- `run.sh` is the single entry point. Its arms are `lint`, `plaintext`, `docs`,
  `vfe`, `gnn`, plus the composites `fast` and `full` and the `report` writer.
  `.github/workflows/ci.yml` calls the arms and no longer carries a second copy
  of any gate command.
- The GNN conformance check moved out of two inline `python3 -` heredocs in the
  workflow into `scripts/check_gnn_conformance.py`. The script reads
  `.github/gnn-pin.json` (schema `gnn-importer-pin/v1`) and repeats none of its
  values; the workflow comment that duplicated the tag and revision is gone.
- New arms: `lint` (`scripts/lint_sources.py`: tracked Python compiles, tracked
  JSON/notebooks parse) and `docs` (`scripts/check_docs.py`: relative links
  resolve, every `docs/` page is reachable from the index).
- `docs/documentation-index.md` is the flat index; `docs/README.md` is the hub
  and links it.
- `docs/_generated/GATES.md` is generated by `./run.sh report`; it holds the
  per-arm wall times, the plaintext file count, the VFE assertion count and the
  pin values. No document hand-copies those numbers.
- CI deduplication: the `plaintext` job dropped its `actions/setup-python` step
  (the arms are standard-library only) and the `gnn-conformance` job dropped
  every install step (the arm provisions the parser itself).

## Before and after

The before numbers are one run of the old commands on the same host, timed with
`/usr/bin/time -p`:

| Gate | Before | After (arm, same host, one run) |
| --- | --- | --- |
| plaintext integrity | `python3 scripts/clean_plaintext.py`, 0.11 s | `./run.sh plaintext`, 0.32 s |
| VFE regression | `julia Chapters/test_vfe.jl`, 4.05 s | `./run.sh vfe`, 5.04 s |
| GNN conformance | inline heredocs in the workflow, never runnable locally | `./run.sh gnn`, 15.56 s |
| lint | none | `./run.sh lint`, 0.12 s |
| docs | none (no link or index gate) | `./run.sh docs`, 0.15 s |
| composite | (the five commands above) | `./run.sh fast` 0.74 s, `./run.sh full` 39.51 s |

`plaintext` and `vfe` run the same commands as before; the differences above
are run-to-run variance on this host, not improvements. The speed gain is in the
default and composite arms: `./run.sh fast` covers lint, links and plaintext in
under a second, and `full` runs everything in about 40 s, dominated by the
pinned parser install (about 15 s).

The GNN arm needs network access. The pinned package declares
`requires-python = ">=3.11,<3.15"` in its own `pyproject.toml`; this host's
default `python3` is 3.15.2, so the arm reads that constraint at the pinned
revision and selects `python3.14` from `PATH` (`GNN_PIN_PYTHON` overrides the
search).
